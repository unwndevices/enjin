### Integration Issues

**1. Canvas4 display path does not apply palette at blit time (PAL-01, SDL-02)**

`getCanvasData128()` in `src/bindings/emscripten_bindings.cpp` returns raw 4-bit palette index values — no palette lookup occurs. `Palette::resolve()` is fully implemented but called by zero production code. The display-time palette application step has no implementation in any output path (WASM or SDL). Phase 21 SDL blit is the planned implementation point, but the WASM path also lacks this step.

```cpp
// Current — returns raw indices, no palette
data[y * width + x] = canvas.getPixel(x, y).value;

// Required — apply palette at display time
uint8_t idx = canvas.getPixel(x, y).value;
if (!g_palette.isTransparent(idx)) {
    RGB c = g_palette.resolve(idx);
    // write c.r, c.g, c.b to output
}
```

**2. getPaletteRGB() snapshot vs. live-view semantics (PAL-05, PAL-03)**

`getPaletteRGB()` populates a `static uint8_t buf[45]` at call time. The SUMMARY documents this as a "live view," but JS callers that cache the returned `Uint8Array` reference will receive stale data after any `setPaletteColor()` call. Must re-call `getPaletteRGB()` after each palette mutation. This calling convention must be documented before Phase 21/22 JS render loops are written.

## Milestone Definition of Done

The roadmap defines v1.3 success criteria across 5 observable truths:

1. A Lua script calling `setPalette(0, 255, 0, 0)` makes pixels drawn with color index 0 render red — **PAL-01, PAL-04: mechanism implemented; display path missing**
2. Pixels drawn at index 15 are skipped (transparent) at the blit step on all platforms — **PAL-02: transparent flag implemented; blit step missing**
3. The WASM JavaScript renderer reads palette colors via `getPaletteRGB()` and applies them during canvas-to-screen compositing — **PAL-05: API exists; no JS renderer consumes it**
4. The default palette provides 15 distinct colors (indices 0-14) visible on screen before any script call — **PAL-01, PAL-03: palette exists; no display path renders it**
5. Palette swap at runtime does not require canvas re-render or reallocation — **PAL-03: satisfied**

Only success criterion 5 is fully closed. The remaining 4 require Phase 21 (SDL blit) or a WASM pixel-expansion function.
