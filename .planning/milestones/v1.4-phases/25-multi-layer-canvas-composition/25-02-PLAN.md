**Add include:**
Add `#include <enjin2/graphics/layer_compositor.hpp>` after the existing canvas.hpp include.

**Replace static globals:**

Remove:
```cpp
static enjin2::Canvas4<CANVAS_W, CANVAS_H> g_canvas;
```
and (inside `#ifdef ENJIN2_BUILD_LUA`):
```cpp
static enjin2::LuaCanvas g_lua_canvas(&g_canvas);
```

Replace with:
```cpp
static enjin2::LayerCompositor<CANVAS_W, CANVAS_H> g_compositor;
```

For the LuaCanvas wrappers: LuaCanvas has no default constructor, so a static array is not directly possible. Instead, declare `LuaCanvas*` pointers and construct them inside `main()` as local statics (which is safe since g_compositor is a file-scope static constructed before main). Use `static` local variables inside `main()`:

```cpp
// Inside main(), before Lua init:
#ifdef ENJIN2_BUILD_LUA
static enjin2::LuaCanvas g_lua_layer0(&g_compositor.layers[0]);
static enjin2::LuaCanvas g_lua_layer1(&g_compositor.layers[1]);
static enjin2::LuaCanvas g_lua_layer2(&g_compositor.layers[2]);
static enjin2::LuaCanvas g_lua_layer3(&g_compositor.layers[3]);
static enjin2::LuaCanvas* g_lua_layers[enjin2::ENJIN_LAYER_COUNT] = {
    &g_lua_layer0, &g_lua_layer1, &g_lua_layer2, &g_lua_layer3
};
#endif
```

**Update Lua initialization:**

Replace `g_lua.setCanvas(&g_lua_canvas)` with `g_lua.setCanvas(g_lua_layers[0])` — sets initial active canvas to layer 0 (background), matching CONTEXT.md decision: "Default active layer at startup/init = layer 1 (Lua index, i.e., C++ buffer 0, background)".

After `g_lua.getBindings().setInput(&g_input)`, add a call to pass the layer canvas array to bindings so Plan 03 can use it. For now, just set the default canvas to layer 0. Plan 03 will add the `setLayers()` call when it adds layer state to LuaBindings.

**Update error handling:** Replace any `g_canvas.clear(enjin2::Pixel4(14))` error-display calls with `g_compositor.layers[0].clear(enjin2::Pixel4(14))` — errors show on layer 0.

**Update expand_canvas_to_rgb:**

Replace `g_canvas.getPixel(x, y)` with `g_compositor.output.getPixel(x, y)`. The function signature stays the same, only the data source changes.

**Update frame loop:**

Insert `g_compositor.clearAll()` BEFORE the Lua update/draw calls (after input polling):

```cpp
// --- Frame loop (revised order) ---
// 1. Input
enjin2::input_advance_frame(&g_input);
enjin2::input_platform_poll(&g_input);

// 2. Auto-clear all layers (layer 0 -> black, 1-3 -> transparent)
g_compositor.clearAll();

// 3. Lua update + draw (draws to active layer via currentCanvas)
#ifdef ENJIN2_BUILD_LUA
g_lua.getBindings().setInput(&g_input);
g_lua.callFunction("update", dt);
g_lua.callFunction("draw");
#endif

// 4. Composite layers -> output
g_compositor.composite();

// 5. Expand + blit
expand_canvas_to_rgb();
SDL_UpdateTexture(...);
```

The key ordering constraint: `clearAll()` before draw, `composite()` after draw, `expand_canvas_to_rgb()` after composite.

**Important:** Do NOT reset the active layer between frames. CONTEXT.md says "setLayer() persists across frames — active layer does NOT reset between draw() calls". Only pixel content is cleared.
