# Milestone v1.0: Migration + Documentation

**Status:** ✅ SHIPPED 2026-02-01
**Phases:** 1-6
**Total Plans:** 21

## Overview

Complete migration from enjin1 to enjin2 with full independence, validation, and comprehensive documentation. enjin2 is now a self-contained library with Lua/WASM integration, non-dynamic memory allocation, and clean intelligent structure.

## Phases

### Phase 1: Dependency Analysis

**Goal**: Understand enjin1→enjin2 dependencies and establish compilation isolation
**Depends on**: Nothing (first phase)
**Plans**: 3 plans

Plans:

- [x] 01-01: Generate dependency graph mapping all enjin1→enjin2 dependencies
- [x] 01-02: Verify no namespace enjin references in enjin2 codebase
- [x] 01-03: Establish compilation isolation with separate CMake targets

**Details:**
Confirmed enjin2 is fully independent of enjin1 at source and build levels. Zero dependencies across 26 source files. CMake graphviz analysis verified no enjin1 libraries or targets in build dependency chain.

### Phase 2: Core Migration

**Goal**: Migrate core infrastructure with compatibility layer
**Depends on**: Phase 1
**Plans**: 3 plans

Plans:

- [x] 02-01: Create compatibility headers for type aliases
- [x] 02-02: Implement Strangler Fig seams for incremental migration
- [x] 02-03: Document memory mapping strategy (shared_ptr → unique_ptr)

**Details:**
Created compatibility headers in namespace enjin for type aliases (Vector2, Size, Vector3) and lifecycle wrapper functions (Awake, Start, Update). Seam infrastructure created but later deleted as migration approach pivoted to enjin2-only. Memory mapping documented for shared_ptr to unique_ptr conversion with scene-based ownership.

### Phase 3: Feature Support

**Goal**: Enable feature migration with abstraction layers
**Depends on**: Phase 2
**Plans**: 3 plans

Plans:

- [x] 03-01: Configure CMake build system for compile-time backend selection
- [x] 03-02: Create abstraction interfaces (ICanvas, IComponent, IScene)
- [x] 03-03: Update seams for compile-time routing with interface implementation

**Details:**
CMake backend selection with USE_ENJIN1 option added (later removed in Phase 5). Abstraction interfaces created: ICanvas (kept for pixel type polymorphism), IComponent and IScene (deleted as unused). Seam infrastructure updated for compile-time routing.

### Phase 4: Validation

**Goal**: Validate behavior through manual testing and shadow mode
**Depends on**: Phase 3
**Plans**: 4 plans

Plans:

- [x] 04-01: Add BMP export capability using stb_image_write library
- [x] 04-02: Create image comparison utility and manual testing infrastructure
- [x] 04-03: Implement shadow mode execution for automated comparison
- [x] 04-04: Create terminal output formatter for test results

**Details:**
Integrated stb_image_write for BMP export (24-bit RGB from 8-bit grayscale). Created manual testing checklist and scripts for component lifecycle, rendering, scene transitions. Shadow mode execution runs both enjin1 and enjin2 in parallel. Image comparison utility for validation. Note: Validation scripts later deleted as user confirmed parity.

### Phase 5: Final Cleanup

**Goal**: Complete enjin2-only build system
**Depends on**: Phase 4
**Plans**: 1 plan

Plans:

- [x] 05-01: Remove CMake options, compile definitions, and conditional compilation for enjin1 backend

**Details:**
Removed all USE_ENJIN1 and USE_ENJIN1_BACKEND references. Simplified seams (deleted Backend/Implementation enums). Clean enjin2-only build system with no conditional compilation. enjin2 compiles and builds successfully with zero enjin1 dependencies.

**Goal:** Create comprehensive library documentation using Doxygen for API extraction and Docusaurus for modern web presentation, deployed to GitHub Pages
**Depends on:** Phase 5
**Plans:** 7 plans

Deployed to GitHub Pages via GitHub Actions workflow.

## Milestone Summary

**Decimal Phases:**
None

**Key Decisions:**
- Fully independent enjin2 - User wants to keep only enjin2 in the end
- Namespace enjin for compatibility layer - separates migration code from enjin2 core
- Compile-time backend selection via CMake option (later removed in favor of enjin2-only)
- Template explicit instantiation for static library linking
- 24-bit RGB BMP format for broad compatibility (8-bit grayscale converted gray=R=G=B)
- xml2js for Doxygen XML parsing instead of manual regex (handles C++ templates, namespaces, overloads)
- Module-based API organization (core, graphics, ui, utils) instead of alphabetical A-Z
- Docusaurus dual-plugin setup with separate plugins for guides and API reference

**Issues Resolved:**
- Dependency overflow at 100+ phases - Resolved with phase splitting
- Context overflow - Resolved with ROADMAP.md split approach
- Phase insertion confusion - Resolved with decimal phase numbering
- MDX compilation errors in API docs - Fixed with escapeMarkdown function
- API sidebar document ID conflicts - Fixed with plugin path exclusion
- Template linking errors - Fixed with explicit template instantiation
- Missing Adafruit-GFX-Library - Fixed with copy to enjin2/include
- INTERFACE library compile definition scope - Fixed by using INTERFACE scope

**Issues Deferred:**
- Compat headers (migration artifacts, minimal usage - used only in benchmarks)
- Examples cleanup (examples/enjin_comparison_benchmark.cpp references enjin1)
- Doxygen warnings (210 warnings during XML generation - acceptable for initial setup)

**Technical Debt Incurred:**
- Seam files deleted before being used (Strangler Fig pattern abandoned for enjin2-only approach)
- Validation scripts deleted (~1,014 lines removed - obsolete after user confirmed parity)
- IComponent and IScene deleted (~180 lines - unused, only needed for seam layer)
- ICanvas kept (used by Canvas4 and Canvas8 for pixel type polymorphism)
