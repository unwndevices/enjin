# Phase 13: Fix Documentation Pipeline & API Landing - Research

**Researched:** 2026-02-23
**Domain:** Doxygen XML to Docusaurus pipeline (Node.js), Docusaurus content plugin configuration
**Confidence:** HIGH

## Summary

Phase 13 fixes the documentation generation pipeline (`scripts/generate-api-docs.js`) which has encoding bugs that cause 12+ C_-prefixed classes, 2 nested classes, and 1 namespaced class to silently fail XML file lookup. The root cause is well-understood: Doxygen encodes underscores in class names as double underscores (`__`) in filenames, but the script's `possibleNames` array doesn't account for this. Separately, nested class config entries use `_` notation instead of `::`, and `math::TrigLUT` uses the wrong separator.

Additionally, the compat module is excluded from the generator config despite having a valid Doxygen group XML, the Effects routing conflict (class named `Effects` in a directory named `effects/`) needs a durable fix, and the `docs/api/` directory needs a landing page so the README's `/api` link resolves properly.

**Primary recommendation:** Fix the XML filename lookup in `processClass()` to handle Doxygen's underscore encoding, update config entries to use `::` notation, add compat module config, rename Effects output to avoid the routing conflict, and create `docs/api/README.md` as the API landing page.

### Pattern 1: Doxygen XML Filename Encoding
**What:** Doxygen encodes special characters in XML filenames. Underscores (`_`) in C++ identifiers become double underscores (`__`). Namespace separators (`::`) become `_1_1`.
**Confidence:** HIGH (verified by examining actual XML files on disk)

**Encoding rules observed:**
```

ComponentQuery::Iterator -> classenjin2_1_1ComponentQuery_1_1Iterator.xml  (:: -> _1_1)
math::TrigLUT         -> classenjin2_1_1math_1_1TrigLUT.xml     (:: -> _1_1)
```

### Pattern 2: Docusaurus Content Plugin Routing
**What:** The API docs use a separate `@docusaurus/plugin-content-docs` instance with `id: 'api'`, `path: 'api'`, `routeBasePath: 'api'`. The sidebar is autogenerated from directory structure.
**Confidence:** HIGH (verified from `docusaurus.config.js`)

**Key detail:** `onBrokenLinks: 'throw'` means the build will fail if any link references a non-existent page. This is actually helpful for catching issues.

### Pattern 3: Module Overview as Category Index
**What:** Each module directory uses `README.md` with `id: moduleName` as the Docusaurus category index page. The `api-sidebar.js` uses `autogenerated` from directory structure.
**Confidence:** HIGH (verified from existing module READMEs)

### Anti-Patterns to Avoid
- **Hardcoding XML filenames:** Don't build a lookup table of special cases. Instead, implement Doxygen's encoding rules properly so ALL class names resolve correctly.
- **Adding slug overrides for every conflict:** The Effects conflict should be resolved by renaming the output file, not by adding slug hacks. The current `slug: /effects/Effects` line in `Effects.md` is the symptom of this anti-pattern.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Doxygen filename encoding | One-off special cases for each C_ class | A proper encoding function that doubles underscores | There are 11 C_ classes now and more may be added later |
| API landing page | Custom HTML or complex routing | A simple `docs/api/README.md` with module links | Docusaurus already supports README.md as category index |

**Key insight:** The underscore encoding fix must be a general solution, not a per-class workaround. Doxygen's encoding rule is consistent: every `_` in the original name becomes `__` in the filename.

## Common Pitfalls

### Pitfall 1: Double-Encoding Underscores
**What goes wrong:** When fixing the underscore encoding, you might apply the doubling to ALL underscores in the generated filename, including the `_1_1` separators that represent `::`.
**Why it happens:** The `::` -> `_1_1` replacement happens first (via `.replace(/::/g, '_1_1')`), then if you blindly double all `_` you'd get `_1__1` instead of `_1_1`.
**How to avoid:** Apply underscore doubling to the class name parts BEFORE replacing `::` with `_1_1`. Process order: (1) split on `::`, (2) double underscores in each part, (3) join with `_1_1`.
**Warning signs:** ComponentQuery::Iterator resolving to wrong filename.

### Pitfall 2: sanitizeClassName Also Collapses Double Underscores
**What goes wrong:** The current `sanitizeClassName()` function has `.replace(/__/g, '_')` which collapses double underscores back to single. This means output filenames for C_ classes will be wrong.
**Why it happens:** This was likely added to clean up `::` -> `_` replacement artifacts, not anticipating C_ class names.
**How to avoid:** When changing config entries to `::` notation, the `sanitizeClassName` function should work correctly. But C_ classes still need careful handling. The `__` collapse needs to be removed or made smarter.
**Warning signs:** Output file named `C_Animation.md` instead of expected name.

### Pitfall 3: Effects Routing Conflict
**What goes wrong:** `Effects.md` (class page) inside `effects/` directory conflicts with `effects/README.md` (module overview). Docusaurus generates routes where `effects/Effects` could clash with the directory.
**Why it happens:** The class is named `Effects` and the module directory is `effects/`. Case-insensitive filesystems or Docusaurus routing can cause conflicts.
**How to avoid:** Rename the Effects class page output to something like `EffectsClass.md` (with adjusted id/title), or adjust the document ID to avoid conflict. The `generateModuleOverview` function already reads existing `.md` files for class links, so renaming the file will automatically update the overview.
**Warning signs:** Docusaurus build throws broken link errors or shows wrong page.

### Pitfall 4: Compat Module Has Different Namespace
**What goes wrong:** Compat module uses `namespace enjin` (not `enjin2`), so the XML lookup for classes uses a different prefix.
**Why it happens:** Compat is a compatibility layer wrapping enjin2 types under the old `enjin` namespace.
**How to avoid:** The XML file for compat's only class (`Vector3`) is `structenjin_1_1Vector3.xml` (note: `enjin` not `enjin2`, and `struct` not `class`). The `processClass` function already tries `classenjin_1_1` as a fallback, but needs to also try `structenjin_1_1`.
**Warning signs:** "XML file not found for Vector3" warning.

### Pitfall 5: API Landing Page Must Match Plugin Config
**What goes wrong:** Creating the landing page in the wrong location or with wrong frontmatter.
**Why it happens:** The API plugin has `path: 'api'` and `routeBasePath: 'api'`, so the landing page must be at `docs/api/README.md` (or `docs/api/index.md`).
**How to avoid:** Use `docs/api/README.md` with frontmatter `slug: /` so it serves as the root of the API plugin. The `id` should be something like `api-landing` to avoid conflicts.
**Warning signs:** 404 at `/enjin/api/` or redirect to random module page.

## Code Examples

### Fix 1: Doxygen Underscore Encoding in XML Filename Lookup

```javascript
// Current broken code (line 210-213):
const possibleNames = [
  `classenjin2_1_1${className.replace(/::/g, '_1_1')}.xml`,
  `classenjin_1_1${className.replace(/::/g, '_1_1')}.xml`,
];

// Fixed code - encode underscores BEFORE joining with _1_1:
function classNameToXmlFilename(className, prefix) {
  // Split on :: for nested classes/namespaces
  const parts = className.split('::');
  // Doxygen doubles underscores in each name part
  const encodedParts = parts.map(part => part.replace(/_/g, '__'));
  // Join with _1_1 (Doxygen's :: encoding)
  return `${prefix}${encodedParts.join('_1_1')}.xml`;
}

const possibleNames = [
  classNameToXmlFilename(className, 'classenjin2_1_1'),
  classNameToXmlFilename(className, 'classenjin_1_1'),
  classNameToXmlFilename(className, 'structenjin2_1_1'),
  classNameToXmlFilename(className, 'structenjin_1_1'),
];
```

### Fix 3: sanitizeClassName Must Handle C_ Classes

```javascript
// Current (breaks C_ classes by collapsing __):
function sanitizeClassName(name) {
  return name
    .replace(/::/g, '_')
    .replace(/<[^>]*>/g, '')
    .replace(/\s+/g, '')
    .replace(/__/g, '_');   // <-- This line is the problem
}

// Fixed - remove the __ collapse since :: is already handled:
function sanitizeClassName(name) {
  return name
    .replace(/::/g, '_')
    .replace(/<[^>]*>/g, '')
    .replace(/\s+/g, '');
  // No longer collapse __ — C_Animation should stay C_Animation
}
```

Note: With `::` notation in config, `ComponentQuery::Iterator` becomes `ComponentQuery_Iterator` which is correct. And `C_Animation` stays `C_Animation` which is also correct.

### Fix 4: Effects Routing Conflict Resolution

```javascript
// In processClass(), when writing the output file, check for conflict
// with the module directory name:
const sanitized = sanitizeClassName(className);
let outputName = sanitized;

// If the sanitized class name matches the module directory (case-insensitive),
// append 'Class' to avoid routing conflict
if (sanitized.toLowerCase() === module.toLowerCase()) {
  outputName = `${sanitized}Class`;
}

const outputFile = path.join(config.outputDir, module, `${outputName}.md`);
```

Alternatively, keep filename as-is but ensure the frontmatter `id` is unique and doesn't conflict. The current code already adds a `slug` for this case. The simplest durable fix is to use a distinct filename.
