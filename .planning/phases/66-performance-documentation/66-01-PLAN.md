- How-to first: show the build-bench.sh command and explain the four binaries
- List each binary and what it benchmarks:
  - bench_canvas: Canvas4/Canvas8 pixel ops, fill, rect, circle, sprite blit, multi-layer composite

**4. CI Pipeline section (DOC-01 — subsystem 2 of 5)**
- How it works: `.github/workflows/benchmarks.yml` triggers on push to main or PRs touching `src/**` or `include/**`
- `scripts/convert-bench.py` converts nanobench JSON to `customSmallerIsBetter` format for github-action-benchmark
- History stored on `bench-data` branch (NOT gh-pages — explain why: docs.yml deploy-pages would wipe history)
- Regression threshold: 150% (shared runner variance; will be tightened after 30-50 baseline runs)
- PR behavior: `fail-on-alert: true` — PRs that regress beyond threshold are flagged
- Push behavior: auto-push results to bench-data branch for history accumulation
- Dashboard URL: the gh-pages performance dashboard shows historical data points

**5. Frame Timing section (DOC-01 — subsystem 3 of 5)**
- How-to first: show the build + run command for SDL3 runner with `--show-timing`:
  ```
  cmake -DENJIN2_BUILD_SDL=ON -DENJIN2_BUILD_LUA=ON -DCMAKE_BUILD_TYPE=Release -B build .
  cmake --build build --target enjin2_sdl
  ./build/src/platform/sdl/enjin2_sdl --show-timing --script scripts/layer_demo.lua
  ```
- Explain FrameTimingInstrumentation: tracks updateTime_us, renderTime_us, luaTime_us, compositeTime_us
- Dual compile-path: `ENJIN2_FRAME_TIMING=1` injected only for enjin2_sdl target; WASM and ESP32 use zero-overhead stub
- Polling API: `FrameTimingInstrumentation::get()` for reading values without the overlay

**6. Lua Profiler section (DOC-01 — subsystem 4 of 5)**
- How-to first: show the enjin_run build + profile command:
  ```
  cmake -DENJIN2_BUILD_LUA=ON -DENJIN2_BUILD_HEADLESS=ON -DCMAKE_BUILD_TYPE=Release -B build-headless .
  cmake --build build-headless --target enjin_run
  ./build-headless/src/platform/headless/enjin_run --profile --frames 100 scripts/my_game.lua
  ```
- JSON output: add `--output json` flag
- Explain LuaProfiler: C-level lua_sethook profiler (LUA_MASKCALL | LUA_MASKRET) with per-function call counts
- Zero overhead when disabled: `lua_sethook(L, NULL, 0, 0)` confirmed when --profile is not passed
- enjin_run stubs all platform APIs (gfx, input) as no-ops — runs headlessly without SDL3

**7. Allocation Verification section (DOC-01 — subsystem 5 of 5)**
- Explain the zero-alloc guarantee: hot paths (canvas pixel ops, component updates, Lua binding calls) must not allocate
- AllocGuard RAII pattern: wraps a scope, counts operator new calls, fails if any detected
- bench_alloc binary: overrides all six operator new/delete forms, runs hot paths under AllocGuard
- CI enforcement: build-bench.sh runs bench_alloc; non-zero exit fails the CI job
- Pitfall: `executeString()` inside AllocGuard — explain the `luaL_ref` + `lua_rawgeti` + `lua_call` pattern for zero-alloc Lua calling

**8. Frame Budgets section (DOC-03)**
- Table with three rows: SDL3 Desktop, WASM, ESP32-S3
- Columns: Platform, Target FPS, Frame Budget, Instrumentation, Notes
- SDL3: 30 fps default (configurable via --fps), 33.3 ms budget, full FrameTimingInstrumentation, measured values in tables above
- WASM: 60 fps (requestAnimationFrame), 16.6 ms budget, NOT instrumented (zero-overhead stub), "WASM benchmarks are not run in CI. Use SDL3 desktop numbers as a conservative upper bound — WASM hot paths may be 2-5x slower depending on Emscripten optimization level."
- ESP32-S3: 60 fps target (dt guard), 16.6 ms budget, NOT instrumented (zero-overhead stub), "ESP32-S3 benchmarks are not run in CI. Measured FPS from the esp32_lcd_demo with strip-pipelined DMA (40-line strips, 80MHz SPI) typically achieves 30-60 fps depending on Lua script complexity."

**9. Adding New Benchmarks section (DOC-02)**
- Walk through 5 steps (exact content from 66-RESEARCH.md "Adding New Benchmarks" section):
  - Step 1: Create the benchmark source file (show template from bench_canvas.cpp pattern with the #define ANKERL_NANOBENCH_IMPLEMENT, doNotOptimizeAway, mkdir + JSON output)
  - Step 2: Register the CMake target in benchmarks/CMakeLists.txt (show add_executable + target_link_libraries with nanobench_vendor + enjin2_core)
  - Step 3: Add to scripts/build-bench.sh (add target to cmake --build line, add run step)
  - Step 4: Add to scripts/convert-bench.py INPUT_FILES list
  - Step 5: Verify in CI (workflow picks up automatically via build-bench.sh and convert-bench.py)
- Key rules callout box: one ANKERL_NANOBENCH_IMPLEMENT per binary, always doNotOptimizeAway(), JSON to bench-results/bench_NAME.json, mkdir before ofstream

- nanobench INTERFACE target pattern (no compilation, header-only path)
