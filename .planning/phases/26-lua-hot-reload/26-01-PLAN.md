**1. Fix LuaCallback dangling-pointer bug in lua_engine.cpp (lines 92-101):**
The `registerFunction(const std::string& name, LuaCallback callback)` overload takes `callback` by value, pushes `&callback` (address of local copy) as a lightuserdata upvalue. This is undefined behavior — the pointer dangles after the function returns.

Fix: Replace the function body with a no-op + warning comment. All current bindings use the `lua_CFunction` overload exclusively (confirmed by codebase inspection). The `LuaCallback` overload is vestigial.

```cpp
void LuaEngine::registerFunction(const std::string& name, LuaCallback /*callback*/) {
    if (!initialized) return;
    // LuaCallback overload is vestigial — all bindings use lua_CFunction.
    // Body intentionally left as no-op to prevent dangling-pointer UB.
    // The lightuserdata approach stored &local which was invalid after return.
}
```

Do NOT remove the declaration from lua_engine.hpp — keep the method signature for ABI compatibility. Just neuter the body.

**3. Add performReload() as a static function:**

Place this **inside the `#ifdef ENJIN2_BUILD_LUA` guard**, above `main()`, or as a lambda/helper. It must be inside the guard to avoid build errors when Lua is disabled.

```cpp
#ifdef ENJIN2_BUILD_LUA
static bool performReload(enjin2::LuaScriptSystem& lua,
                          enjin2::LuaCanvas** layers,
                          uint8_t count,
                          bool* visible,
                          enjin2::InputState* input,
                          const std::string& path)
{
    lua.shutdown();
    if (!lua.initialize()) {
        std::cerr << "[reload error] Lua init failed\n";
        return false;
    }
    lua.getBindings().setLayers(layers, count, visible);
    lua.getBindings().setInput(input);
    enjin2::LuaResult r = lua.loadScript(path);
    if (r.success) {
        std::cerr << "[reload] " << path << "\n";
        return true;
    }
    std::cerr << "[reload error] " << r.error << "\n";
    return false;
}
#endif
```

Key details:
- `lua.initialize()` calls `bindings.registerAll()` internally, which now also resets the sprite pool and drawing state (from Task 1).
- `setLayers()` resets `activeLayer = 0` and `currentCanvas = layerCanvases[0]` — no separate layer reset needed.
- `setInput()` re-wires the input pointer.
- Do NOT call `bindings.registerAll()` explicitly — `initialize()` already does it.
