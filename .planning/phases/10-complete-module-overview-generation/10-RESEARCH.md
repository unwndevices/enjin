# Phase 10: Complete Module Overview Generation - Research

**Researched:** 2026-02-03
**Domain:** Docusaurus documentation generation, XML parsing, API doc organization
**Confidence:** HIGH

## Summary

This phase requires generating Docusaurus module overview (landing) pages by parsing Doxygen group XML files and creating README.md files in each module directory. The existing `scripts/generate-api-docs.js` script generates class/namespace documentation but doesn't create module overview pages, creating an integration gap identified in v1.1 audit.

**Primary recommendation:** Use Docusaurus's category index convention (README.md in folder) combined with xml2js parsing to generate module overview pages that automatically integrate with the existing autogenerated sidebar.

### Pattern 1: Docusaurus Category Index Convention

**What:** Place README.md in a directory; Docusaurus automatically treats it as the category's landing page.

**When to use:** When using autogenerated sidebars with folder-based categories.

**Example:**

**Source:** https://docusaurus.io/docs/sidebar/autogenerated#category-index-convention

```
docs/api/core/README.md  ← Automatically becomes category landing page
docs/api/core/Object.md  ← Category item

api-sidebar.js:
module.exports = {
  apiSidebar: [{ type: 'autogenerated', dirName: '.' }],
};
```

Result: "Core" category links to `/api/core/README.md`, all class files under it are listed.

### Pattern 2: xml2js Async Parsing

**What:** Use xml2js.parseString() with Promise wrapper for XML parsing.

**When to use:** Parsing Doxygen group XML files.

**Example:**

```javascript
// Source: https://github.com/Leonidas-from-XIV/node-xml2js
function parseXmlFile(filePath) {
  const xmlContent = fs.readFileSync(filePath, 'utf-8');
  return new Promise((resolve, reject) => {
    xml2js.parseString(xmlContent, (err, result) => {
      if (err) reject(err);
      else resolve(result);
    });
  });
}
```

### Pattern 3: Module Overview Page Content

**What:** Generate markdown with title, description, and class list links.

**Example:**

```javascript
function generateModuleOverview(moduleName, title, brief, detailed, classes) {
  let markdown = `---
id: ${moduleName}
title: ${title}
sidebar_label: ${title}
---

# ${title}

${brief}

${detailed}

## Classes

${classes.map(cls => `- [${cls}](./${cls})`).join('\n')}
`;
  return markdown;
}
```

### Anti-Patterns to Avoid

- **Manual sidebar configuration:** Don't manually add category items to sidebars.js—autogenerated handles it
- **Parsing group XML for member lists:** Group XML doesn't contain member info; use config.modules.classes
- **Using _category_.yml:** Overkill for simple landing pages; README.md works automatically
- **Skipping modules in config:** Only generate README for modules in config.modules (excludes compat)

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| XML parsing | Custom regex/string parsing | xml2js | Handles nested XML, namespaces, edge cases |
| Category page linking | Manual sidebar config | README.md + category index convention | Built-in Docusaurus feature, auto-updating |
| Class listing | Manual mapping | config.modules.classes | Already exists, consistent with existing code |
| Module name to XML mapping | String manipulation logic | Config-based mapping | Explicit, maintainable |

**Key insight:** Docusaurus's category index convention is specifically designed for this use case—no custom sidebar manipulation needed.

## Common Pitfalls

### Pitfall 1: Generating README for modules without classes

**What goes wrong:** Empty or minimal module overview page with no class links.

**Why it happens:** Some modules (like compat) exist in XML but aren't in config.modules.

**How to avoid:** Only process modules in config.modules, skip group XML files for missing modules.

**Warning signs:** Module README.md exists but has no classes section.

### Pitfall 2: XML parsing errors on missing files

**What goes wrong:** Script crashes when group XML file doesn't exist.

**Why it happens:** Not all group XML files may be generated by Doxygen.

**How to avoid:** Check file existence with fs.existsSync() before parsing, log warning and continue.

**Warning signs:** Error: ENOENT: no such file or directory when running script.

### Pitfall 3: Incorrect module name mapping

**What goes wrong:** Wrong group XML file accessed (e.g., group__core__group.xml vs group__Core__group.xml).

**Why it happens:** Inconsistent naming between module names and group IDs.

**How to avoid:** Use explicit mapping: `group__${moduleName}_group.xml` matches pattern in existing code.

**Warning signs:** Module overview shows wrong description or XML parsing fails.

### Pitfall 4: Overwriting existing README files

**What goes wrong:** Manual edits to module overview pages are lost on regeneration.

**Why it happens:** Script generates README.md every time without checking if manual edits exist.

**How to avoid:** Acceptable tradeoff for automated generation; document that README files are auto-generated.

**Warning signs:** Users report losing custom content in module overview pages.

## Code Examples

### Process Group XML and Generate Overview

```javascript
// Source: Existing parseXmlFile pattern in generate-api-docs.js:90-98
async function processGroup(moduleName, moduleInfo) {
  const groupXml = path.join(config.xmlDir, `group__${moduleName}_group.xml`);

  if (!fs.existsSync(groupXml)) {
    console.log(`Warning: Group XML not found for ${moduleName}`);
    return null;
  }

  const xml = await parseXmlFile(groupXml);
  const compound = xml.doxygen.compounddef[0];
  const title = extractText(compound.title);
  const brief = extractText(compound.briefdescription);
  const detailed = extractText(compound.detaileddescription);

  // Generate module overview markdown
  const markdown = generateModuleOverview(moduleName, title, brief, detailed, moduleInfo.classes);

  // Write README.md to module directory
  const outputPath = path.join(config.outputDir, moduleName, 'README.md');
  fs.writeFileSync(outputPath, markdown);
  console.log(`Generated module overview: ${moduleName}/README.md`);

  return outputPath;
}
```
