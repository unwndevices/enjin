**1. Overview**
- engine.ui.* functions are stateless immediate-mode draw calls
- Each call reads arguments, draws to the active canvas, and returns immediately
- No per-call allocation, no retained state between frames, no pool, no refs
- UI calls bypass C++ Label/FillUpGauge components (std::string incompatible with zero-alloc pipeline)

**2. Anatomy of a UI Function**
Show the exact pattern with a concrete example (use progressBar or a hypothetical new function like `engine.ui.checkbox`):

```
1. REQUIRE_CANVAS guard (early return 0 if no canvas)
2. Extract arguments from Lua stack (luaL_checkinteger for pixel coords/colors, luaL_checknumber for floats)
3. Validate/clamp input values
4. Call LuaCanvas methods (fillRect, drawRect, drawText, etc.)
5. return 0 (no values pushed to Lua)
```

**3. Available Canvas Primitives**
List all LuaCanvas methods available for UI composition:
- fillRect(x, y, w, h, color) — filled rectangle
- drawRect(x, y, w, h, color) — rectangle outline
- drawLine(x1, y1, x2, y2, color) — line
- drawCircle(x, y, r, color) — circle outline
- fillCircle(x, y, r, color) — filled circle
- drawText(str, x, y, color, size, font) — text rendering
- drawTextWrapped(str, x, y, maxWidth, color, size, font) — wrapped text

**4. Wiring Checklist**
Step-by-step for adding a new function:
1. Declare `static int lua_engine_ui_newFunc(lua_State* L);` in bindings.hpp private section
2. Implement in bindings_ui.cpp as `int LuaBindings::lua_engine_ui_newFunc(lua_State* L) { ... }`
3. Add entry to `kUIFuncs[]` array in registerUISubtable()
4. (No CMakeLists.txt change needed unless creating a new .cpp file)

**5. Hot-Reload Contract**
- Because UI functions are stateless (no pool, no refs, no cleanup), they survive hot-reload (F5) automatically
- registerAll() does NOT need a resetUIState() call
- setActiveScene() does NOT need UI cleanup
- Contrast with coroutines/tweens which DO need pool cleanup on reload

**6. Color Model**
- All colors are palette indices (uint8_t)
- 4-bit canvas: indices 0-15
- 8-bit canvas: indices 0-255
- Consistent with all existing draw bindings

**7. Anti-Patterns**
- Do NOT use std::string, std::vector, or any heap allocation
- Do NOT store state between calls (no member variables for UI)
- Do NOT create Lua registry refs (no luaL_ref)
- Do NOT pull in Label.hpp or FillUpGauge.hpp headers
- Do NOT use luaL_checkinteger for float parameters (truncates 0.5 to 0)
- Do guard division by zero for ratio parameters

**8. Testing Pattern**
- UIFixture (no canvas): tests null-canvas safety and table existence
- UICanvasFixture (with Canvas4<128,128>): tests pixel-level draw correctness
- Use canvas.getPixel(x, y) for pixel verification
- Add test to tests/CMakeLists.txt under ENJIN2_BUILD_LUA guard
