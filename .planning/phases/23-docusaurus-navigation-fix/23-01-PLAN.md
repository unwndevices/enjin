**Category A — Apply `escapeForMdx()` to 8 prose extraction sites (DOC-02):**

The existing `escapeForMdx()` function is already present and correct. It is simply not called on prose description fields. Wrap the following 4 pairs of `extractText()` calls (8 total) with `escapeForMdx()`:

1. In `processClass()` — class-level descriptions (around lines 263-264):
```javascript
// BEFORE:
const briefDesc = extractText(compound.briefdescription);
const detailedDesc = extractText(compound.detaileddescription);

// AFTER:
const briefDesc = escapeForMdx(extractText(compound.briefdescription));
const detailedDesc = escapeForMdx(extractText(compound.detaileddescription));
```

2. In `processClass()` — member method descriptions (around lines 284-285, inside the member loop):
```javascript
// BEFORE:
briefDesc: extractText(member.briefdescription),
detailedDesc: extractText(member.detaileddescription),

// AFTER:
briefDesc: escapeForMdx(extractText(member.briefdescription)),
detailedDesc: escapeForMdx(extractText(member.detaileddescription)),
```

3. In `processNamespace()` — namespace-level descriptions (around lines 397-398):
```javascript
// BEFORE:
const briefDesc = extractText(compound.briefdescription);
const detailedDesc = extractText(compound.detaileddescription);

// AFTER:
const briefDesc = escapeForMdx(extractText(compound.briefdescription));
const detailedDesc = escapeForMdx(extractText(compound.detaileddescription));
```

4. In `processNamespace()` — namespace member descriptions (around lines 414-415, inside the member loop):
```javascript
// BEFORE:
briefDesc: extractText(member.briefdescription),
detailedDesc: extractText(member.detaileddescription),

// AFTER:
briefDesc: escapeForMdx(extractText(member.briefdescription)),
detailedDesc: escapeForMdx(extractText(member.detaileddescription)),
```

**DO NOT** wrap the `signature` field — `formatMethod()` already calls `escapeForMdx()` internally. Wrapping it again causes double-escaping (`&amp;lt;`). Only the `briefDesc`/`detailedDesc` fields need this treatment.

**Category B — Remove namespace names from `config.modules.utils.classes` (DOC-01):**

The names `Colors`, `DrawingHelpers`, `Noise`, `Polar`, and `Signals` are namespaces — they have no `classenjin2_1_1X.xml` file, only `namespaceenjin2_1_1X.xml`. They are already handled by `processNamespace()` via `config.namespaces`. Keeping them in `utils.classes` causes `processClass()` to log "Warning: XML file not found for X" on every run.

Find the `utils` entry in the `config.modules` object and change it to:
```javascript
utils: {
  classes: ['InputSystem', 'math::TrigLUT'],  // namespace names removed; handled by config.namespaces
  description: 'Utility functions and helpers',
},
```

Note: `math::TrigLUT` remains — it IS a class (`classenjin2_1_1math_1_1TrigLUT.xml` exists) and correctly stays in `utils.classes`. Only the five namespace names are removed.

- Grep the file to confirm `Colors` no longer appears in the `utils.classes` array
