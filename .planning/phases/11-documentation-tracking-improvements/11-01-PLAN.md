<task type="auto">
  <name>Task 1: Add Doxygen warning threshold gate to CI workflow</name>
  <files>.github/workflows/docs.yml</files>
  <action>
Insert a new step in `.github/workflows/docs.yml` immediately AFTER the "Generate Doxygen XML" step (the `cmake --build . --target docs` step) and BEFORE the "Generate API documentation" step.

The new step should be named "Check Doxygen warning count" and must:

1. Set `WARNING_FILE="doxygen-warnings.log"` and `THRESHOLD=20`
2. Check that the warning file exists — if not, emit `::error::` and `exit 1`
3. Count actual warnings using `grep -c ": warning:" "$WARNING_FILE" || true` (not `wc -l`, which counts continuation lines too — see research pitfall 4)
4. Print the count and threshold for visibility
5. If count exceeds threshold: emit `::error::` with the count, write a summary to `$GITHUB_STEP_SUMMARY` showing warning count and the first 30 lines of the log, then `exit 1`
6. If count is within threshold: emit `::notice::` confirming success

IMPORTANT: The Doxygen warning log is written to the REPO ROOT (not build/), because the CMake docs target uses `WORKING_DIRECTORY ${CMAKE_CURRENT_SOURCE_DIR}`. The CI step runs from the default directory (also repo root), so the path is just `doxygen-warnings.log` with no directory prefix.

Use the exact implementation from 11-RESEARCH.md "Recommended: CI Warning Check Step" code example.
  </action>
  <verify>
Verify the step is correctly positioned in docs.yml:
- Read docs.yml and confirm "Check Doxygen warning count" step exists between "Generate Doxygen XML" and "Generate API documentation"
- Confirm the step uses `grep -c ": warning:"` (not `wc -l`)
- Confirm threshold is set to 20
- Confirm file existence check is present
- Validate YAML syntax: `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/docs.yml'))"`
  </verify>
  <done>
docs.yml contains a "Check Doxygen warning count" step that reads doxygen-warnings.log, counts warnings with grep, and exits non-zero if count exceeds 20. YAML is valid.
  </done>
</task>
