       # Welcome to enjin2

       enjin2 is a lightweight C++ game engine designed for embedded systems and resource-constrained environments. Built with static memory allocation and a component-based architecture, enjin2 provides powerful graphics, scene management, and Lua scripting capabilities without dynamic heap allocation.

       ## Key Features

       - **Component-Based Architecture**: Build game entities by composing reusable components
       - **Static Memory Allocation**: No dynamic heap allocation after initialization (embedded-friendly)
       - **Scene Management**: Built-in scene state machine with transitions
       - **Graphics Abstraction**: Canvas-based rendering with support for multiple pixel formats
       - **Lua Scripting**: Integrated LuaJIT engine for dynamic game logic
       - **Cross-Platform**: Support for ESP32-S3, WebAssembly, and desktop platforms

       ## Architecture Overview

       enjin2 is organized into modular layers:

       - **Core**: Foundation types, Object/Component system, Scene management
       - **Graphics**: Canvas abstraction, drawing primitives, text rendering
       - **Components**: Reusable game logic (drawable, position, sprite, Lua script)
       - **UI**: User interface widgets and layout managers
       - **Scripting**: Lua engine integration and bindings
       - **Animation**: Keyframe-based animation system
       - **Utils**: Helper functions and algorithms
       - **Effects**: Post-processing and visual effects

       ## Getting Started

       See [Getting Started](/docs/guides/getting-started) for installation instructions and your first enjin2 project.

       ## API Reference

       Explore the [API Reference](/api) for detailed documentation of all enjin2 classes and functions.

       # Getting Started

       This guide will help you get enjin2 running on your platform and create your first game.

       ## Prerequisites

       - **C++17 compatible compiler**: GCC 7+, Clang 5+, or MSVC 2017+
       - **CMake 3.16+**: Build system
       - **Platform-specific tools** (choose one):
         - **ESP32-S3**: ESP-IDF 5.0+ or PlatformIO
         - **WebAssembly**: Emscripten SDK 3.1+
         - **Desktop**: System Lua or LuaJIT

       ## Building from Source

       ```bash
       # Clone the repository
       git clone git@github.com:unwndevices/enjin.git
       cd enjin

       # Configure build
       cmake -B build

       # Build library
       cmake --build build
       ```

       ## Your First Scene

       Create a simple scene with a rotating sprite:

       ```cpp
       #include <enjin2/core/object.hpp>
       #include <enjin2/core/scene.hpp>
       #include <enjin2/components/position.hpp>
       #include <enjin2/components/sprite.hpp>

       using namespace enjin2;

       class RotatingSprite : public Scene {
       public:
           void onCreate() override {
               auto obj = createObject();
               obj->addComponent<C_Position>(Point(64, 64));
               obj->addComponent<C_Sprite>(spriteData);
           }
       };
       ```

       ## Running Examples

       ```bash
       # Build examples
       cmake --build build --target examples

       # Run an example
       ./build/examples/basic_drawing
       ```

       # Architecture Overview

       enjin2 uses a component-based architecture designed for static memory allocation and embedded systems.

       ## Component System

       The Object-Component pattern separates game entities into:
       - **Objects**: Containers that hold components
       - **Components**: Modular pieces of functionality

       ```cpp
       auto obj = createObject();
       obj->addComponent<C_Position>(Point(64, 64));
       obj->addComponent<C_Sprite>(spriteData);
       obj->addComponent<C_Animation>(animationData);
       ```

       Benefits:
       - Compose functionality from reusable components
       - Each component manages specific behavior
       - Static allocation prevents runtime memory fragmentation

       ## Layer Structure

       ### Core Layer
       Foundation types and base classes:
       - `Object`: Game entity container
       - `Component`: Base class for all components
       - `Scene`: Container for game state
       - `SceneStateMachine`: Scene management and transitions
       - `Signal`: Event notification system

       ### Graphics Layer
       Hardware-agnostic drawing:
       - `ICanvas`: Drawing interface (templated on pixel type)
       - Primitives: Lines, rectangles, circles, text
       - Sprite rendering with anchoring
       - Effects (CRT simulation, pixel effects)

       ### Components Layer
       Reusable game logic:
       - `C_Position`: 2D position with rotation
       - `C_Drawable`: Base for renderable components
       - `C_Sprite`: Image rendering
       - `C_Animation`: Keyframe animations
       - `C_LuaScript`: Lua behavior attachment

       ## Memory Management

       enjin2 uses **static memory allocation**:
   - Components stored in fixed-size arrays (max 16 per Object)
   - Objects managed in ObjectCollection with static allocation
   - No `new`/`delete` after initialization

       ## Scene Lifecycle

       1. `onCreate()`: Scene initialization (one-time setup)
       2. `onActivate()`: Called when scene becomes active
       3. `onUpdate(deltaTime)`: Per-frame game logic
       4. `onRender(canvas)`: Per-frame rendering
       5. `onDeactivate()`: Called when scene becomes inactive
       6. `onDestroy()`: Scene cleanup (one-time)

       # Components

       Components are the building blocks of enjin2 objects. Each component manages specific functionality.

       ## Creating Components

       Components inherit from the `Component` base class:

       ```cpp
       class MyComponent : public Component {
       public:
           void awake() override {
               // Called when component is added to an active object
           }

           void start() override {
               // Called once after awake
           }

           void update(float deltaTime) override {
               // Called every frame
           }

           void lateUpdate(float deltaTime) override {
               // Called after all updates
           }
       };
       ```

       ## Built-in Components

       ### C_Position
       Manages 2D position and rotation:
       ```cpp
       obj->addComponent<C_Position>(Point(64, 64), 0.0f);
       ```

       ### C_Sprite
       Renders sprites with anchoring and layering:
       ```cpp
       obj->addComponent<C_Sprite>(spriteData);
       ```

       ### C_Animation
       Plays keyframe animations:
       ```cpp
       obj->addComponent<C_Animation>(animationData);
       ```

       ### C_LuaScript
       Attaches Lua behavior:
       ```cpp
       obj->addComponent<C_LuaScript>(scriptPath);
       ```

       ## Component Lifecycle

       1. **awake()**: Initialization when added to active object
       2. **start()**: Called once after all awake() calls
       3. **update()**: Per-frame updates
       4. **lateUpdate()**: After all updates, before rendering

       ## Drawing Components

       Components that render should extend `C_Drawable`:

       ```cpp
       class MyDrawable : public C_Drawable {
       public:
           void draw(ICanvas& canvas) override {
               canvas.fillRect(position.x, position.y, 10, 10);
           }
       };
       ```

       # Scenes

       Scenes manage game states, objects, and transitions.

       ## Creating a Scene

       Extend the `Scene` base class:

       ```cpp
       class MyScene : public Scene {
       public:
           void onCreate() override {
               // One-time setup: create objects, load resources
               auto obj = createObject();
               obj->addComponent<C_Position>(Point(100, 100));
               obj->addComponent<C_Sprite>(spriteData);
           }

           void onActivate() override {
               // Called when scene becomes active
           }

           void onUpdate(float deltaTime) override {
               // Per-frame game logic
           }

           void onRender(ICanvas& canvas) override {
               // Per-frame rendering
               Scene::onRender(canvas); // Render all objects
           }

           void onDeactivate() override {
               // Called when scene becomes inactive
           }

           void onDestroy() override {
               // Cleanup: release resources
           }
       };
       ```

       ## Scene State Machine

       Manage multiple scenes with transitions:

       ```cpp
       SceneStateMachine machine;

       // Register scenes
       machine.addScene<MainMenuScene>(1);
       machine.addScene<GameScene>(2);

       // Change scene
       machine.changeScene(2, TransitionType::IMMEDIATE);
       ```

       ## Transitions

       Built-in transition effects:

       - `IMMEDIATE`: Instant change
       - `FADE_OUT_IN`: Fade out, switch scenes, fade in
       - `SLIDE_LEFT`: Slide new scene from left
       - `SLIDE_RIGHT`: Slide new scene from right

       ```cpp
       // Fade transition over 500ms
       machine.changeScene(2, TransitionType::FADE_OUT_IN, 500);
       ```

       ## Object Management

       Create and manage objects in scenes:

       ```cpp
       // Create object
       auto obj = createObject();

       // Add components
       obj->addComponent<C_Position>(Point(64, 64));
       obj->addComponent<C_Sprite>(spriteData);

       // Find objects
       auto foundObj = findObject(objectId);

       // Destroy object
       destroyObject(objectId);
       ```
