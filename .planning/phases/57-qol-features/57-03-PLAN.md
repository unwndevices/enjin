**Test implementations:**

**test_tween_await_suspends_and_resumes (QOL-01):**
- Start a tween on a Lua table from 0 to 100 over a short duration (e.g., 0.1s).
- Start a coroutine that calls `engine.tween.await(id)` then sets a global flag `g_resumed = true`.
- Tick with dt=0.05 (coroutine ticks first, then tween). Verify `g_resumed` is still false (coroutine suspended).
- Tick with dt=0.1 (tween should complete at t>=1.0). Verify `g_resumed` is now true.
- ASSERT g_resumed == true after tween completion tick.
- Use a Lua global string flag rather than a C-side boolean to avoid shared state issues. Use `lua_getglobal(L, "g_resumed")` and `lua_toboolean`.

**test_tween_await_invalid_id_resumes_immediately (QOL-01):**
- Start a coroutine that calls `engine.tween.await(9999)` (nonexistent ID) then sets `g_resumed = true`.
- Tick once with tickBoth(0.016). Verify `g_resumed` is true (coroutine ran to completion immediately because tween not found).
- ASSERT g_resumed == true after single tick.

**test_tween_await_resumes_exactly_once (QOL-01):**
- Create a tween with 0.1s duration.
- Start TWO coroutines, both calling `engine.tween.await(same_id)`. Each sets a different global: `g_a = true`, `g_b = true`.
- Tick until tween completes. Verify both g_a and g_b are true.
- ASSERT both are true.

**test_wait_frames_yields_exactly_n (QOL-02):**
- Start a coroutine: `engine.async.wait_frames(3)` then sets `g_resumed = true`.
- Use tickBoth (or just tickCoroutines since no tween involved).
- After 1 tick: g_resumed is false. After 2 ticks: false. After 3 ticks: true.
- ASSERT g_resumed == false after tick 1, false after tick 2, true after tick 3.

**test_wait_frames_zero_resumes_immediately (QOL-02):**
- Start a coroutine: `engine.async.wait_frames(0)` then sets `g_resumed = true`.
- Tick once. ASSERT g_resumed == true.

**test_wait_frames_negative_resumes_immediately (QOL-02):**
- Start a coroutine: `engine.async.wait_frames(-5)` then sets `g_resumed = true`.
- Tick once. ASSERT g_resumed == true.

**test_dead_zone_freezes_camera (QOL-03):**
- Create CamFixture. Create a target Object with C_Position. Set position to (5.0, 5.0) (inside dead zone).
- Set camera position to (0, 0) via `cam->lookAt(0, 0, 1.0f)` with a large dt to snap it (or use setPosition if available).
- Call `engine.camera.follow(proxy, 0.5)` and `engine.camera.setDeadZone(20, 20)` via Lua.
- Record cam position before tick. Call tickCameraFollow(0.1f). Record cam position after.
- ASSERT camera position is unchanged (both x and y within tolerance 0.001f).
- Target at (5,5) with camera at (0,0): dx=5, dy=5. Dead zone is 20x20, so half is 10x10. 5 <= 10: inside → freeze.

**test_dead_zone_resumes_on_exit (QOL-03):**
- Same setup. Move target to (50.0, 50.0) (outside dead zone: dx=50 > 10, dy=50 > 10).
- Call tickCameraFollow(0.1f). ASSERT camera position has changed (moved toward target).

**test_dead_zone_zero_disables (QOL-03):**
- Same setup. Call `engine.camera.setDeadZone(0, 0)`. Target at (5, 5) (would be inside a non-zero dead zone).
- Call tickCameraFollow(0.1f). ASSERT camera position has changed (not frozen — dead zone disabled).

**Implementation notes:**
- For tween tests: call `luaL_dostring(L, "local id = engine.tween.to(t, {x=100}, 0.1) ...")` where `t` is a Lua table pre-pushed into a global. Or define `t` inside the Lua string.
- For dead zone tests: create a target Object with C_Position, get proxy via Lua `engine.scene.find(name)`, then pass proxy to `engine.camera.follow`. Alternatively, write the setup entirely in Lua via dostring.
- tickBoth order: tickCoroutines THEN tickTweens. The tween.await resume fires inside tickTweens; the coroutine must have already yielded (set up by a prior tickCoroutines call or during the same tick's initial run).
- Dead zone tests: use `cam->getPosition()` to read camera position before/after tick.
