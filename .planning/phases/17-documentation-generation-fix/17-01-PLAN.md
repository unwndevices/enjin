In `scripts/generate-api-docs.js`, make two changes:

**1. Add ordered parsing options to `parseXmlFile()` (line ~97)**

Change the `xml2js.parseString()` call to include options:
```javascript
xml2js.parseString(xmlContent, {
  explicitChildren: true,
  preserveChildrenOrder: true,
  charsAsChildren: true
}, (err, result) => { ... });
```

These three options together cause xml2js to produce `$$` arrays containing children in document order, with text nodes represented as `{ "#name": "__text__", "_": "text content" }` entries.

IMPORTANT: All three options are required. `preserveChildrenOrder` creates `$$` arrays, `charsAsChildren` includes text nodes in those arrays, `explicitChildren` enables child element tracking. In xml2js 0.6.x, both `$$` (ordered) AND named properties (grouped) are present simultaneously, so existing code using `compound.sectiondef`, `member.name[0]`, etc. continues to work unchanged.

**2. Rewrite `extractText()` function (lines ~105-118)**

Replace the current `extractText()` with:
```javascript
function extractText(node) {
  if (!node) return '';
  if (typeof node === 'string') return node;
  if (Array.isArray(node)) return node.map(extractText).join('');
  if (typeof node === 'object') {
    // Ordered children available — walk in document order
    if (node.$$) {
      return node.$$.map(child => {
        if (child['#name'] === '__text__') return child._ || '';
        // For element children (ref, para, etc.), recurse
        return extractText(child);
      }).join('');
    }
    // Fallback: use _ property (leaf text content)
    if (node._ !== undefined) return String(node._);
    // Fallback: iterate non-$ properties (preserves Phase 14's $ filter)
    return Object.entries(node)
      .filter(([key]) => key !== '$' && key !== '#name' && key !== '$$')
      .map(([, value]) => extractText(value))
      .join('');
  }
  return '';
}
```

Key design decisions:
- Primary path: `$$` array traversal for correct document order (fixes DOCG-01, DOCG-04)
- `__text__` nodes carry interstitial text content
- Fallback to `_` property for leaf nodes without children
- Fallback to `Object.entries()` with `$`, `#name`, `$$` filtered out (preserves Phase 14's `$` filter plus filters new ordered-mode keys)
- No dual traversal: `$$` is always preferred when available

DO NOT:
- Remove the `$` key filter from the fallback path (it prevents xml2js attribute leaking)
- Keep the old Object.entries-only approach as primary (it loses document order)
- Try to fix parameter name/description concatenation (out of scope for Phase 17)

In `scripts/generate-api-docs.js`, make two changes:

**1. Fix const const duplication in `formatMethod()` (line ~177-193)**

The current code:
```javascript
const args = method.argsstring ? method.argsstring[0] : '()';
```

Doxygen XML includes trailing ` const` in `argsstring` AND sets `$.const = 'yes'` as a separate attribute. `formatMethod()` appends ` const` based on the attribute, producing `() const const`.

Fix: After extracting `args`, strip trailing ` const` if the const attribute is set:
```javascript
let args = method.argsstring ? method.argsstring[0] : '()';
const isConst = method.$.const === 'yes';
// Strip trailing const from argsstring to avoid duplication
// (Doxygen includes it in argsstring AND as a separate attribute)
if (isConst && args.endsWith(' const')) {
  args = args.slice(0, -6);
}
```

Note: Change `const args` to `let args` to allow mutation. Keep the rest of `formatMethod()` unchanged — the `${isConst ? ' const' : ''}` at the end is the single source of truth.

**2. Remove stale compat module from config.modules (lines ~25-28)**

Delete the entire `compat` entry from `config.modules`:
```javascript
    compat: {
      classes: ['Vector3'],
      description: 'Compatibility layer for enjin1 integration',

```

Phase 16 deleted the compat source headers. Keeping this config entry would recreate `docs/api/compat/` during regeneration, partially undoing Phase 16 cleanup.

Also delete the `docs/api/compat/` directory if it exists:
