<task type="auto">
  <name>Integrate processGroup into main execution flow</name>
  <files>scripts/generate-api-docs.js</files>
  <action>Modify the main() function in scripts/generate-api-docs.js (around line 408) to call processGroup for each module before processing classes:

Find the module iteration loop:
```javascript
  // Process classes in each module
  for (const [moduleName, moduleInfo] of Object.entries(config.modules)) {
    console.log(`\nProcessing ${moduleName} module...`);

    for (const className of moduleInfo.classes) {
      const result = await processClass(className, moduleName, moduleInfo);
      if (result) generatedFiles++;
    }
  }
```

Replace with:
```javascript
  // Process classes in each module
  for (const [moduleName, moduleInfo] of Object.entries(config.modules)) {
    console.log(`\nProcessing ${moduleName} module...`);

    // Generate module overview page
    const overviewResult = await processGroup(moduleName, moduleInfo);
    if (overviewResult) generatedFiles++;

    // Generate class documentation
    for (const className of moduleInfo.classes) {
      const result = await processClass(className, moduleName, moduleInfo);
      if (result) generatedFiles++;
    }
  }
```

This generates README.md before processing classes for each module. The order doesn't matter functionally, but generating overview first matches user expectation of seeing module description first.
