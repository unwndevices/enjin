**bindings_engine.cpp — three changes:**

1. **Add to kSceneFuncs array** (add two entries after "destroy"):
   ```cpp
   {"persist",   lua_engine_scene_persist},
   {"unpersist", lua_engine_scene_unpersist},
   ```
   Update ENJIN_ARRAY_LEN usage — it auto-computes from the array, so just adding entries is sufficient.

2. **Implement lua_engine_scene_persist (PERSIST-01):**
   - Arg 1: ObjectProxy userdata (use `luaL_testudata(L, 1, "ObjectProxy")`)
   - Null-guard: if proxy is nullptr, or !proxy->valid, or !proxy->object, push nil and return 1
   - Get LuaBindings via `getBindings(L)`, null-guard m_ssm
   - Call `b->m_ssm->persistObject(proxy->object)`
   - If returns false (pool full or not found in scene), push nil and return 1
   - If returns true, push boolean true and return 1
   - Do NOT invalidate the proxy — the object is still alive, just moved to registry ownership

3. **Implement lua_engine_scene_unpersist (PERSIST-02):**
   - Arg 1: ObjectProxy userdata (same pattern as persist)
   - Null-guard: proxy nullptr/invalid/null-object -> push nil, return 1
   - Get LuaBindings via getBindings(L), null-guard m_ssm
   - Call `b->m_ssm->unpersistObject(proxy->object)`
   - Push boolean true, return 1
   - Note: unpersist marks for removal on NEXT transition, not immediate destruction

4. **Extend lua_engine_scene_find (PERSIST-03):**
   After the existing scene search (line ~375 `Object* obj = scene->findByName(name);`), add a fallback:
   ```cpp
   if (!obj) {
       LuaBindings* b = getBindings(L);
       if (b && b->m_ssm) {
           obj = b->m_ssm->findPersistentByName(name);
       }
   }
   ```
   This goes BEFORE the existing nil-return check (`if (!obj) { lua_pushnil(L); return 1; }`). The rest of the function (ObjectProxy allocation) remains unchanged.

   **Search priority:** Active scene first, then persistent registry. This matches the recommended approach from research — callers in the current scene expect local objects to take precedence.

**Important:** The `getBindings(L)` helper retrieves LuaBindings* from the Lua registry. Check how camera_follow or other bindings do this — it may use `lua_getfield(L, LUA_REGISTRYINDEX, "enjin_bindings")` or an upvalue pattern. Use the same mechanism. If persist/unpersist are static methods of LuaBindings, they can access m_ssm via the getBindings helper (same as camera follow pattern from Phase 48).

**Scene setup pattern for each test:**

- Set scene 1 as active: `ssm.switchTo(1); ssm.update(0.016f); bindings.setActiveScene(ssm.getCurrentScene());`

- Persist via Lua: `result = engine.scene.persist(g_obj)`
- Switch scene: execute `engine.scene.switch(2)` from Lua, then call `ssm.update(0.016f)` from C++ to trigger deferred transition, then `bindings.setActiveScene(ssm.getCurrentScene())`
- Verify via Lua: `found = engine.scene.find("hero") ~= nil`
